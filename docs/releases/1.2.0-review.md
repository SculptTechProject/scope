# Scope 1.2.0: reusable HAR Action and refreshed identity

This proposal integrates original PR heads #3, #15, #22 and #23 through real merge
parents. It includes pinned GitHub Actions updates, Lucide/TypeScript upgrades,
the offline HAR comparison composite Action and new brand/icon assets. The
dependency notice followup includes the exact upgraded Lucide license text.
Branch protections, native maintainer approval and required platform checks stay
enabled.

Application, npm lock, Cargo workspace/local package lock entries and Tauri
versions agree on **1.2.0**. The private HAR experiment/lab package versions keep
their separate 0.1.0 identifiers. This is a backward-compatible feature release;
capture/replay semantics and archive formats do not change.

## Review the resulting behavior

- Linux workflows can invoke the bundled offline comparison through a composite
  Action, get JSON/HTML/JUnit paths and distinguish clean/regression/invalid
  results. Minimized labels are the default; raw captures and reports are never
  uploaded automatically. Deferred failure requires a caller-owned final gate.
- Output directories must be new; the wrapper invokes its own CLI with an argument
  array, bounds child execution/output and preserves safe diagnostics. Local
  subprocess tests use a separate synthetic consumer workspace.
- The cyan two-path mark, banner and desktop icon files replace the old identity.
  The banner is generated brand artwork, with source/provenance recorded in
  `docs/BRAND.md`; historical application screenshots are unchanged.
- Generated notices match committed locks and include Lucide's updated copyright
  and Feather MIT text. Native Frida files remain excluded from public packages.

## Validation and publication

The original dependency heads passed hosted macOS/Windows/Linux build, package
and real engine/MCP smoke jobs. Their success does not establish the final
combined candidate. This proposal requires fresh exact-head platform CI and
the isolated HAR/browser checks. The composite Action's hosted gate must validate
its real YAML invocation, outputs and failure behavior separately from local
entrypoint tests. Exact local checks are recorded in `docs/VERIFICATION.md`.

After native maintainer approval and successful required checks, merge through
normal protection. Tag the reviewed main commit as `v1.2.0`, build it into a draft,
inspect platform manifests/resources and verify checksums before publication.
The proposal itself creates no tag or public release and does not rewrite 1.1.0
assets.

## Remaining limits

Interactive 1.2.0 desktop/device checks are unperformed unless separately recorded.
Prior-version macOS/Android observations are historical evidence. Windows/Linux
interactive behavior remains experimental; Intel macOS is unverified. macOS uses
ad-hoc signing, without Apple notarization. The initial Action runner target is
Linux with caller-supplied Node/Bash; local subprocess tests are not proof of a
hosted runner result. Bodies remain buffered at 16 MiB each, and report label
minimization does not guarantee anonymity. See `docs/DEPENDENCIES.md` for existing
upstream findings.
