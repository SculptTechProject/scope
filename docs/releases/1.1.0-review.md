# Scope 1.1.0: filters, offline HAR contracts and leaner imports

This release proposal integrates the reviewed work from #18, #19 and #20 through
real merge parents, preserving their original commits. It also fixes CODEOWNERS
after the maintainer account rename and updates the existing bot-authored
proposal flow to accept a matching release branch/version. Branch protections,
required platform checks and approving review remain enabled.

## User-visible changes

- Combine desktop traffic predicates before pagination: method, exact host,
  status, plain body text, lifecycle and edited state. Ordinary literal search
  remains available; invalid structured queries clear stale rows and explain
  how to recover. MCP retains its separate sanitized literal-search boundary.
- Compare two saved HAR files locally with exact operation selection, scoped
  ignores and explicit status/JSON requirements. The separate Node CLI produces
  deterministic JSON, escaped offline HTML and JUnit with exits 0/1/2.
- Native session import consumes its owned exchange tree instead of cloning it.
  Validation/transaction behavior is preserved. The committed bounded Linux
  debug benchmark measures lower peak RSS, without a speed or streaming claim.

Application, npm lock, Cargo workspace/local package lock entries and Tauri
versions agree on **1.1.0**. This is a backward-compatible feature release;
existing capture/archive formats, free features and AGPL notices remain intact.
The HAR CLI ships in the source archive; it is not a new native desktop command.

## Review and validation gates

The three original PR heads passed their hosted platform/CodeQL checks and
independent bounded source/privacy review before integration. This proposal
requires fresh combined CI for its exact head: macOS/Windows/Linux full workspace
tests, frontend tests, public-resource checks, packaging and real stdio MCP smoke,
plus isolated HAR and sandboxed Chromium/CSP checks.

Locally, rerun the frontend build/tests, release-resource tests, device helper
tests and offline HAR product/lab/demo/DOM checks. The local review environment
does not provide Rust/native desktop prerequisites; hosted results remain
separate evidence. A source version bump is not evidence of a published release.

After the maintainer reviews and approves this exact proposal, merge through
normal protection. A separate explicit release gate chooses the reviewed main
commit and tag, builds platform assets into a draft, verifies checksums/build
manifests and publishes the reviewed draft. No tag or public release is created
by this proposal.

## Known limits

Interactive desktop/device validation of 1.1.0 remains unperformed unless a
later verification record explicitly adds it. Prior macOS/Android observations
do not become new-version evidence. The macOS package is ad-hoc signed and not
Apple-notarized. Windows/Linux interactive behavior remains experimental.
Bodies are still buffered up to 16 MiB each; no streaming or long-session memory
bound is claimed. Readable report labels can be sensitive; minimized labels do
not anonymize interaction patterns. Existing dependency/platform limitations
remain documented in `docs/DEPENDENCIES.md`.
